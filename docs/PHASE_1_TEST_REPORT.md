## 真实来源检查的具体结果

以北京时间 2026-10-12 的早报窗口执行。该次验证在当晚进行，源的最新列表已经包含大量早报截止时间之后的内容，因此不能全部纳入本期。

| 来源 | 读取条目 | 时间窗内条目 | 状态 |
|---|---:|---:|---|
| BBC Business | 43 | 5 | 可读取 |
| BBC Technology | 21 | 0 | 可读取，本期列表无符合时间条件条目 |
| BBC World | 24 | 12 | 可读取 |
| 中国新闻网时政 | 30 | 0 | 可读取，本期列表无符合时间条件条目 |
| 中国新闻网财经 | 30 | 0 | 可读取，本期列表无符合时间条件条目 |
| 中国新闻网综合 | 30 | 0 | 可读取，本期列表无符合时间条件条目 |

分类与去重后生成 **8 条**新闻；报告正确显示 `partial`，没有为了填满栏目而修改原发布时间或编造新闻。新闻区域按内容判断，因此国际来源也可能产出中国相关条目。详情和 Markdown 下载接口均返回 200。

这次结果证明了真实管道能够运行，同时验证了首日历史覆盖限制：即使来源返回 HTTP 200，也不代表仍提供整段早报窗口的数据。持续运行时每 30 分钟缓存可减轻此问题，不能保证全部新闻完整留存。该次采集数据保存在隔离验证目录中，不随源码交付，用户首次运行使用自己的数据库。

## 尚未验证或未包含的部分

1. **真实 AI 服务**：未配置用户的模型账号、密钥或计费服务；模型摘要准确率、中文翻译质量、供应商参数兼容性和真实费用尚未验证。
2. **Windows + Docker 端到端运行**：当前执行环境没有 Docker CLI，也不是 Windows；提供了 Compose、Dockerfile 和 PowerShell 指令，未宣称已在用户电脑部署。
3. **浏览器视觉与交互验收**：已完成响应式代码、类型检查和构建；未执行浏览器截图、手机真机或键盘读屏验收。
4. **连续 24 小时运行**：验证了队列、恢复逻辑与 worker 启动，没有实际等待到次日 08:00，也没有进行长期耐久性测试。
5. **全领域编辑质量**：规则分类可能误分，默认来源不保证中国科技等栏目每日满额；需要用户网络下验证来源、模型联调和抽样核对。
6. **GitHub 远端**：已准备 CI 和推送说明，没有创建/推送远程仓库，没有运行远端 GitHub Actions。
7. **后续阶段**：用户系统、收藏、全文搜索、Android/iOS、推送和预测图表均未实现；对应设计和验收条件已列出。

## 用户本地首轮验收

1. 执行 `docker compose up --build -d`，确认 API、worker、frontend 正常运行。
2. 打开 `http://localhost:3000`，查看自动任务在线状态；触发或等待一份日报，检查原文链接、时间窗与来源异常提示。
3. 填入可用模型配置并重新创建 API/worker；重跑后确认出现 `AI 已分析`，手工核对摘要与来源是否一致。
4. 重启服务后检查已生成的历史日报仍存在；检查手机尺寸下筛选、阅读和返回功能。
5. 在电脑保持运行的条件下，次日查看 08:00 任务和完成时间；确认没有重复日期或重复通知（MVP 尚无推送）。

本报告把代码验证、真实来源验证和用户环境部署验证分开记录，避免把“能构建”当作“已上线”。
